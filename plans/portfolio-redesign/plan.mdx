# Portfolio Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use `superpowers:executing-plans` to implement this plan task-by-task. Use `superpowers:subagent-driven-development` only if the user explicitly requests delegated execution.

**Goal:** Replace the current résumé-style single page with a fast, responsive, dark-only engineering portfolio that presents three evidence-backed case studies, records useful analytics, resolves at `uthmanallison.com`, and gives search engines complete crawl and identity signals.

**Architecture:** Keep GitHub Pages and ship plain, semantic HTML plus one shared CSS file and one small analytics/consent script. The home page is the concise hiring surface; three static case-study routes carry the depth needed by recruiters and search engines. AwaLedger's backend and financial-insights worker are one system story because their Pub/Sub and webhook contracts make sense together.

**Tech stack:** HTML5, CSS Grid/Flexbox, minimal browser JavaScript, GitHub Pages, GA4, Google Search Console, DNS. No React, bundler, package manager, template engine, database, or paid service.

**Spec:** `plans/portfolio-redesign/plan.mdx` — design decisions and implementation steps are colocated so there is one source of truth.

## Global constraints

- The production experience is dark mode only and declares `color-scheme: dark`; no theme toggle ships.
- Preserve GitHub Pages deployment from the repository root on `main`.
- Use **Abiodun Uthman Allison** as the canonical identity in page titles, structured data, the social card, and Search Console. Compact navigation may use the preferred display name **Uthman Allison**.
- Publicly identify AwaLedger and AI-4AI by their product and organization names. Use only repository-backed technical claims plus the confirmed employment dates; do not infer team, scale, or business impact.
- Do not expose secrets, private source excerpts, customer data, internal URLs, or screenshots that are not approved for public use.
- Meet WCAG 2.2 AA for contrast, keyboard operation, focus visibility, semantic structure, and reduced motion.
- Keep pages useful without JavaScript; analytics and consent are progressive enhancement.
- Every page gets a unique title, description, canonical URL, one `h1`, social metadata, and a path in `sitemap.xml`.
- Avoid external UI/icon libraries and new build dependencies. Reuse the current portrait, résumé PDF, and local font assets only where they earn their cost.

</RichText>

<Callout id="architecture-decision" tone="decision">

Use a multi-page static site. Four hand-authored HTML documents plus one privacy page are smaller and easier to operate than adding React, Astro, Jekyll, or a client-side router. Shared CSS owns the visual system; repeated header/footer markup is accepted at this scale.

</Callout>

## Explicit non-goals

- No blog, CMS, admin panel, contact-form backend, newsletter, authentication, search, theme switcher, animated particle background, or résumé data pipeline.
- No invented business metrics or claims that code alone cannot prove.
- No migration away from GitHub Pages.
- No attempt to guarantee a Google ranking position; the release creates sound technical and content foundations.

## Visual direction

The portfolio should feel like a **systems casebook**, not a developer template or dashboard. Use an asymmetric hero, editorial project records separated by structural rules, and small architecture diagrams that explain invariants. Spend visual emphasis on the case-study system maps; keep the rest calm.

Typography reuses the existing local assets: Raleway Semibold/Bold for headings and Lato Regular/Bold for prose. Body lines stay below 72 characters, headings use sentence case, and labels are not tracked-out all caps. The palette extends the current navy identity into a dark-only midnight/brass system rather than using the common black-and-neon developer aesthetic.

Desktop uses a sticky full-width top bar and a 72rem content measure. Mobile keeps a visible two-link priority navigation instead of adding a hamburger and JavaScript. Project records change from a three-column row to a linear article; nothing is hidden at smaller widths.

## Case-study content grounded in the repositories

### Job Search Agent

**Problem:** Job discovery across multiple providers produces inconsistent data, duplicates, weak geographic fit, and expensive semantic evaluation. Multi-user schedules and notifications add ownership, retry, and privacy boundaries.

**Story to publish:** A Python 3.13/FastAPI system that ingests résumé, website, and manual preferences into a versioned profile; queries SerpApi, Himalayas, Jooble, and Adzuna through bounded adapters; normalizes and deduplicates listings; applies deterministic hard filters before LLM scoring; runs one reusable LangGraph; persists explainable history in PostgreSQL; schedules work safely; and delivers idempotent Resend digests. Highlight privacy-projected LangSmith traces and per-run LLM cost ceilings as production judgment.

**Architecture visual:** Inputs and versioned profile at the top; search/normalize/filter/score graph in the middle; PostgreSQL history, LangSmith traces, logs, and email outcomes as separate operational records.

**Repository evidence:** `README.md`, `src/job_notifier/graph/graph.py`, `src/job_notifier/search/`, `src/job_notifier/scoring/`, `src/job_notifier/scheduling/`, `src/job_notifier/observability/`, `src/job_notifier/persistence/`.

### AI-4AI Offline Literacy Platform

**Problem:** Learners must consume course content and record progress when connectivity is absent or unreliable, then safely reconcile with authoritative server state across retries and devices.

**Story to publish:** A NestJS 11/TypeScript backend for a Flutter learning app. The server owns published content versions, delta manifests, tombstones, stable content identities, idempotent outbox replay, and conflict resolution. Redis serves the hot content-version path; PostgreSQL holds durable state; S3-compatible storage supplies signed assets; Firebase/JWT guard users and admins. Show why content version and learner-state cursor are deliberately separate.

**Architecture visual:** A two-lane online/offline sync: content version to manifest and verified asset download in one lane; progress outbox push, conflict merge, and authoritative pull in the other.

**Repository evidence:** `openwiki/quickstart.md`, `openwiki/offline-first.md`, `docs/offline-first-architecture.md`, `src/modules/domain/content-version/`, `src/modules/domain/content-manifest/`, `src/modules/domain/user/sync-progress/`.

### AwaLedger

**Problem:** Financial document processing and AI classification are expensive and failure-prone; they must not block the transactional API or duplicate side effects when brokers retry delivery.

**Story to publish:** One system spanning two repositories. The FastAPI backend uses clean architecture, PostgreSQL/SQLModel, OCR/storage adapters, an idempotency middleware, and a transactional outbox. It publishes financial-insight events to GCP Pub/Sub only after durable state exists. A detached Python worker validates each message, acquires a Redis distributed lock, uses Gemini 2.5 Flash Lite through LangChain for structured classifications and business insights, posts results through secure idempotent webhooks, and chooses ack/nack behavior by failure class. This page should make the boundary between transactional state and AI work visible.

**Architecture visual:** User/document to FastAPI and PostgreSQL; outbox to Pub/Sub; worker to Redis and Gemini; signed webhook back to the API. Annotate delivery, locking, retry, and persistence boundaries.

**Repository evidence:** `Backend-Repo/README.md`, `docs/background_tasks.md`, `src/infra/pubsub/outbox_dispatcher.py`, `financial-insights-worker/README.md`, `src/worker.py`, `src/insights/`.

Each case study follows the same readable order: Overview, problem, constraints, architecture, key decisions, reliability/security, engineering outcomes, and what I would improve next. “Engineering outcomes” uses verifiable properties until user-supplied metrics are available.
